# 더샵 검단레이크파크 입주예정자협의회 홈페이지

입예협 카페, 위임동의서 접수, 단체민원 안내를 한곳에서 연결하는 새 홈페이지입니다. PC에서는 넓은 메인 화면과 2열 항목을, 모바일에서는 1열 화면과 펼침 메뉴를 보여줍니다. 별도 설치나 빌드 과정은 필요하지 않습니다.

이 홈페이지는 **`geomdan-lakepark` GitHub Organization에서 공동 관리**합니다. 임원들은 각자의 GitHub 계정으로 저장소의 문구·링크·디자인과 기능을 함께 수정할 수 있습니다. 별도의 관리자 편집 화면은 없습니다. 저장소의 파일 변경을 `main`에 저장하면 GitHub Pages 게시 과정에 따라 홈페이지에 반영됩니다.

## GitHub에 적용하기

공식 홈페이지의 저장소 이름은 **`geomdan-lakepark.github.io`**, 소유자는 **`geomdan-lakepark` Organization**으로 지정합니다. 이 전달본을 새 저장소에 올리면 아래 대표 주소로 운영할 수 있습니다. 기존 `council-action` 저장소는 그대로 유지할 수 있으며, 새 홈페이지에도 민원 안내 사본을 포함했습니다. [GitHub Organization 홈페이지 주소 규칙](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

- 홈페이지: https://geomdan-lakepark.github.io/
- 홈페이지 안의 민원 안내: https://geomdan-lakepark.github.io/complaints/index.html

1. 전달된 ZIP을 압축 해제하고 `council-home` 폴더를 엽니다.
2. GitHub에서 **New repository**를 선택하고 Owner를 `geomdan-lakepark`, Repository name을 `geomdan-lakepark.github.io`, 공개 범위를 **Public**으로 지정합니다. **Add a README**를 체크한 뒤 저장소를 만듭니다. 같은 이름의 저장소가 이미 있으면 그 저장소를 사용합니다. 저장소에서 **Add file → Upload files**를 선택합니다. 빈 저장소라 메뉴가 보이지 않으면 첫 화면의 **uploading an existing file** 링크를 선택합니다.
3. **`council-home` 폴더 안의 파일과 폴더를** 업로드 화면에 끌어 놓습니다. `assets`와 `complaints`의 내부 구조를 유지해 주세요. ZIP 자체나 바깥 `council-home` 폴더를 올리면 안 됩니다.
4. 업로드 목록에 `index.html`, `site.config.js`, `assets/...`, `complaints/index.html`이 표시되는지 확인합니다. `council-home/index.html`로 표시되면 한 단계 안쪽으로 잘못 올린 것입니다. 기존 파일이 있는 저장소에서는 같은 경로의 파일이 교체됩니다.
5. 숨김 파일인 `.nojekyll`도 저장소 최상위에 포함합니다. 파일 목록에 보이지 않으면 **Add file → Create new file**에서 이름을 `.nojekyll`로 지정해 추가하면 됩니다. `README.md`는 안내 문서로, 업로드는 선택 사항입니다.
6. 변경 설명에 `입예협 홈페이지 리뉴얼`을 적고 **Commit changes**로 저장합니다. 기존처럼 `main`에 직접 저장할 수 있으며, 임원 검토를 거치려면 새 브랜치에 저장한 뒤 변경 제안을 병합하면 됩니다. [GitHub 파일 업로드 안내](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)
7. **Settings → Pages**에서 게시 설정을 확인합니다. 이미 저장소 최상위에서 게시 중이라면 기존 설정을 유지합니다. 브랜치 방식으로 처음 설정하는 경우 **Deploy from a branch / 파일을 저장한 브랜치(예: main) / /(root)**를 선택합니다. 게시가 완료되면 위 홈페이지를 새로고침하고 카페·위임동의서·민원 버튼을 확인합니다. 배포 상태는 저장소의 **Actions**에서 확인할 수 있습니다. [GitHub Pages 게시 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

저장소 최상위의 구조는 다음과 같습니다.

| 파일·폴더 | 역할 |
| --- | --- |

| `.nojekyll` | 정적 파일 게시 설정 |

## 임원 공동 수정

각 임원에게 저장소 수정 권한을 부여한 뒤 GitHub에서 파일을 열고 연필 모양 **Edit** 버튼으로 수정합니다. 저장된 변경사항은 게시 설정에 따라 홈페이지에 반영됩니다. 메뉴와 문구를 바꿀 때는 우선 **`site.config.js`**를 수정하면 됩니다.

| 바꾸려는 내용 | 설정 위치 |
| --- | --- |
| 협의회 이름 | `brand` |
| 메인 공식 홈페이지 표기·이미지·좌우 배경 | `hero` |
| 위임동의서 접수 링크·안내 문구·블록 이름 | `delegation` (`labels`, `totalCaption` 포함) |
| 집계 시트·집계 기준·갱신 간격 | `delegation.source` |
| 카페·단체민원 등 항목 | `sections` |
| 상단 메뉴 순서 | `navigation` |
| 하단 소개 문장 | `footer` |

- **숨기기:** 해당 항목의 `visible: true`를 `visible: false`로 변경합니다. 관련 메뉴도 함께 제외됩니다.
- **삭제하기:** `sections`에서 해당 항목의 `{ ... }` 묶음을 삭제합니다. `navigation`의 같은 항목 참조도 정리해 주세요.
- **추가하기:** `sections`의 기존 항목을 복사해 `id`, `title`, `description`, `url`, `buttonLabel`을 바꿉니다. 새 항목은 메뉴에도 자동으로 추가됩니다. 별도 이미지가 없으면 `image: ''`로 둡니다.
- **순서 바꾸기:** 화면 항목은 `sections` 배열 순서, 메뉴는 `navigation` 순서입니다. 위임동의서 현황은 별도의 주요 영역이며 `delegation.visible`로 숨길 수 있습니다.

상단 단지명 아래에는 `brand.subtitle`에 적힌 ‘입주예정자협의회 공식 홈페이지’가 표시됩니다. 대문 문구는 `hero.title`입니다. PC에서는 첫 줄 단지명을 화면 낭독용으로 제공하고 둘째 줄을 이미지 속 단지명 아래에 표시합니다. 모바일에서는 전체 대문 비율을 보존한 뒤 두 줄 제목을 함께 표시합니다. 전체 제목은 ‘더샵 검단레이크파크 입주예정자협의회 공식 홈페이지’입니다.

홈 화면은 대문과 **위임동의서·카페·단체민원 세 기능 영역**으로 구성했습니다. 대문 아래에 반복되던 설명과 두 버튼은 제거했습니다. 얇고 어두운 상단바와 대문을 연결하고, 기능 영역은 흰색·옅은 청색·깊은 남색으로 구분합니다.

상단 사이트명은 화면 왼쪽, 세 메뉴는 오른쪽으로 배치합니다. 최하단은 전체 사이트명과 ‘주민의 의견을 모아, 함께 더 나은 내일을 만듭니다.’ 두 문구만 왼쪽 정렬로 표시합니다.

`id`는 소문자 영문으로 시작하고 영문·숫자·하이픈만 사용합니다. 예: `survey`, `move-in`. 다른 항목이나 화면 요소와 겹치는 이름은 사용할 수 없습니다. 외부 링크는 `https://...`, 내부 민원 링크는 `complaints/index.html`처럼 상대경로로 적습니다. 링크가 비어 있으면 준비 중 안내가 표시됩니다. 따옴표·쉼표·괄호는 유지하고, 수정 후 화면을 확인해 주세요.

디자인이나 기능을 개편할 때는 `index.html`, `assets/css/home.css`, `assets/js/home.js`를 공동으로 수정할 수 있습니다. 기존 민원 문안과 일정은 `complaints/index.html`에서 변경합니다.

## 구글 시트 자동 연동

현재 연동 대상은 제공받은 [구글 시트](https://docs.google.com/spreadsheets/d/1C3gHaLJsCd5_1-8KYq5zHkuBX3lpO_W4XVTzY_c2pT0/edit?gid=1484309037)의 **동호수_현황** 탭입니다. A열의 블록과 G열의 교차검증상태를 사용합니다. Google에서 블록·상태별 세대수를 먼저 집계하고, 홈페이지는 집계 결과만 받습니다. 동·호수나 주민별 인증 내역을 브라우저로 내려받지 않습니다.

| G열의 상태 | 동의 세대수에 포함 |
| --- | --- |
| `1·2차 확인완료` | 포함 |
| `입주예정자 미인증 · 위임동의 제출완료` | 포함 |
| `미인증·미제출`, `위임동의 미제출` 등 그 밖의 상태 | 제외 |

- **22블록:** A열이 `22BL`인 세대 중 위 두 완료 상태의 세대수 합계 ÷ `22BL`의 전체 세대수 × 100.
- **23블록:** A열이 `23BL`인 세대 중 위 두 완료 상태의 세대수 합계 ÷ `23BL`의 전체 세대수 × 100.
- **통합:** 두 블록의 동의 세대수 합계 ÷ 두 블록 전체 세대수 합계 × 100. 블록별 비율의 단순 평균을 사용하지 않습니다.
- 분모에는 미제출·미인증 상태도 포함합니다. 이 탭은 **세대당 한 행**이라는 기준으로 계산하므로 동호수 목록을 중복 등록하지 않도록 유지해 주세요. 헤더인 1행은 제외하며 `A2:G`의 끝 행을 제한하지 않아 추가된 세대 행도 포함합니다.
- 시트의 상태 문구와 `delegation.source.acceptedStatuses`가 정확히 일치해야 동의 세대수로 합산합니다. 인증과 위임을 모두 확인한 세대만 표시하려면 배열에 `1·2차 확인완료`만 남기고 `basis`도 해당 기준 설명으로 변경합니다. 이때 제외한 상태는 `pendingStatuses`에 추가합니다.
- 홈페이지를 열면 집계를 조회하고, 화면이 열려 있는 동안 **약 60초마다** 다시 조회합니다. 시트를 수정할 때 홈페이지 파일을 다시 올릴 필요는 없습니다. Google의 처리·캐시·네트워크에 따라 반영이 지연될 수 있습니다. 화면을 다시 열거나 새로고침하면 다시 조회합니다.
- 좌상단 시각은 홈페이지가 집계를 **조회한 시각**이며, 시트의 마지막 수정 시각을 의미하지 않습니다. 시각은 한국시간으로 표시합니다.
- 집계 숫자가 비어 있거나 블록·열 구조가 바뀐 경우 이를 0%로 처리하지 않습니다. 첫 조회 실패는 `— %`, 갱신 실패는 이전 값과 `갱신 지연`을 표시하며 재조회합니다. 전체 세대수와 미완료 상태가 정상적으로 확인되지만 완료 상태가 한 건도 없으면 실제 0%입니다. G열이 빈 세대는 전체 세대수에만 포함하며, 블록의 상태가 모두 비어 있거나 알려진 상태가 하나도 없으면 집계를 표시하지 않습니다. 실제 0%와 100%는 각각 빈 진행 구간과 완전히 채워진 원으로 표현합니다.
- `enabled: false`로 설정하면 자동 조회를 중지하고 준비 중 화면을 사용합니다. 새 집계 파일로 바꿀 때는 `spreadsheetId`, 탭의 `gid`, 범위와 `blockValues`, 상태 배열을 변경합니다. 현재 조회 코드는 `A=블록, G=교차검증상태` 구조를 사용합니다.
- 공개 홈페이지 방문자는 Google 로그인을 요구받지 않습니다. 따라서 집계 파일은 로그인 없이 읽을 수 있어야 합니다. [Google 공식 연동 안내](https://developers.google.com/chart/interactive/docs/spreadsheets)
- 현재 제공 파일은 로그인 없이 조회됩니다. **집계 결과만 요청하는 것은 원본 파일의 공유 권한을 제한하는 기능이 아닙니다.** 홈페이지 공개용 집계와 주민별 인증·신청 기록은 별도 파일로 관리하는 것이 좋습니다. 별도 집계 파일이 만들어지면 해당 구조에 맞춰 연동 코드를 변경하고, 홈페이지 디자인은 그대로 사용할 수 있습니다.

## 화면과 연결 확인

- 카페는 `https://cafe.naver.com/tslp`, 위임동의서는 `https://form.naver.com/response/3xC5swspWEY`로 연결됩니다.
- **위임동의서 현황은 두께감 있는 도넛 지표 세 개로 디자인했습니다.** PC·모바일 모두 왼쪽 ‘22블록’, 중앙 ‘통합 동의율’, 오른쪽 ‘23블록’을 한 줄에 표시하며, 통합 원을 더 크게 강조합니다. 화면 너비를 고르게 3등분하고, 그래프 추가 전의 현황 영역 높이를 유지합니다. 별도의 큰 제출 버튼 대신 영역 전체를 누르면 위임동의서 작성 페이지가 새 창에서 열립니다. 키보드로도 같은 링크를 사용할 수 있습니다.
- 집계 조회 전에는 ‘— % / 집계 준비 중’으로 표시하고, 정상 조회 후 실제 동의율로 바뀝니다. 도넛은 **12시 방향에서 시작해 반시계 방향으로** 채워집니다. 실제 수치가 없는 회색 원은 0%를 뜻하지 않습니다.
- 메인은 제공받은 **더샵 검단레이크파크 대문 이미지**입니다. 원본 비율과 문구·로고를 유지하며 웹용 WebP 파일로 최적화했습니다. 대문 높이는 PC 380~500px으로 줄였고, 좌우는 원본과 같은 분위기로 생성한 숲 배경에 자연스럽게 연결합니다. 모바일에서도 원본 전체 비율을 유지합니다. ‘입주예정자협의회 공식 홈페이지’는 웹 글자로 표시합니다. 이후 이미지를 교체할 때는 `hero.image`, `hero.backdrop`, `hero.imageAlt`를 수정하고, 이미지 속 문구 위치가 달라지면 CSS의 `.hero-title` 위치도 조정합니다.
